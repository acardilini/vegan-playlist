# Admin UI standard

Admin screens exist for fast, repeated curator work, so they favour density and one-click state over explanation. Follow these when building or touching any admin panel (song workbench, artist workbench, queues). `VideoPanel.jsx` and `LinksPanel.jsx` (with `PlatformLinksSection.jsx`) in `frontend/src/components/admin/` are the reference implementations.

1. **A list of items is a table.** A header row of small uppercase labels, narrow fixed columns for choices (radios, checkboxes), and ONE flexible name column. Use the shared classes in `admin.css`: `.adm-list` (the `<ul>`), `.adm-head`, `.adm-row`, `.adm-col-choice` (a fixed ~2.6rem column), `.adm-col-name` (takes all leftover width, ellipsis), `.adm-pill` (a small type/status pill), `.adm-x` (a small icon button), and for link/field rows `.adm-col-label` (the fixed label column), `.adm-col-field` (the flexible input column; use `<AutoText inline>` for an autosaving input), `.adm-col-open` (a small right-aligned Open/Search cell) and `.adm-actions` (one line of grouped buttons under a table).
2. **The thing the curator inspects gets the leftover width.** A link or title the curator clicks to check something is the flexible column and is never squeezed by controls. Controls go in fixed narrow columns.
3. **State is shown, not announced by a button.** Use a radio, checkbox or small tag for "which one is primary / used for X". Do not use a button whose label flips ("Use for audio" / "Use primary"). Put the state in a column with a header so two choices (Show, Audio) read side by side.
4. **At most about three controls per row.** Destructive actions are a small ✕ (`.adm-x`) with a tooltip (`title`) and `aria-label`, and keep a confirm. Headers are hidden when a list has one item and the choices are moot.
5. **Density.** Panel body text `0.85rem`, secondary text and pills `0.7-0.75rem`, controls `btn-sm` / `input-sm`, spacing and colour from tokens only (`--space-*`, `--text-*`, `--border-hairline`).
6. **What you need while doing another task lives in the pinned top bar.** The workbench top bar stays on screen, so a control the curator needs mid-task (for example **Listen**, which opens the video the audio analysis uses while the curator reads lyrics) goes there as a small text link in the existing links row, styled like its neighbours, not as a big button and not behind a scroll.

**Adopting it.** New panels follow this from the start. Existing panels (Links, Platform links, Lyrics, Details, the artist workbench) adopt it when next touched; do not restyle them in passing without a reason.
