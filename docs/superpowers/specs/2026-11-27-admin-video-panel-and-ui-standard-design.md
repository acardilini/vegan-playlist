# Admin video panel and a standard for admin lists - design

**Why.** Adding the "audio analysis video" controls crowded the song workbench's Video panel: each video row holds six things on one line and the title link, the thing the curator clicks to check a video, is the only part allowed to shrink, so it is squeezed to nothing. More widely, admin panels get cluttered quickly, with type and controls larger than they need to be. The curator wants quicker, denser admin screens and one standard approach that the artist workbench can be built on too.

**How the curator works in this panel (their words).** Try Find videos and tick the right ones; if none fit, Search YouTube and paste URLs with a type. While checking lyrics they scroll down to the Video panel just to click the video link and listen. With more than one video they check which is primary and, if they want a different one analysed, set that.

**Goals.** (1) A Video panel whose rows show the title in full and put choices where they can be seen and changed in one click. (2) A "Listen" control that is reachable without scrolling. (3) A small written standard plus reusable CSS for admin lists, so later panels and the artist workbench follow one pattern. **Non-goals.** No restyle of the other panels now (they adopt the standard when next touched); no embedded player now; no change to the data model or routes.

**Approaches (curator chose from mockups).** Row layout: (A) table with two radio columns, **chosen**; (B) two lines per video (rejected: taller); (C) tags plus a ⋯ menu (rejected: two clicks per change, state hidden). Listen: (A) button in the pinned top bar, **chosen**; (B) in the Lyrics heading; (C) embedded player in the Lyrics panel (a possible later upgrade).

**Design.**
- **Video rows become a table.** Header row with small labels, then one line per video: **Show** radio (the primary), **Audio** radio (the video the analysis hears; the primary's row is checked when there is no override), the title as a link that takes all remaining width, a small type pill, a small ✕ delete (keeps the existing confirm). The Show and Audio headers and radios appear only when the song has 2+ videos; a single video is just title, pill, ✕. Choosing Audio on the primary's row clears the override (as today). The old "Use for audio" / "Use primary" buttons and the "audio analysis" tag go: the radios are the state. Find videos and Search YouTube stay in one tools line; the add row (URL, type, Add) stays on one line.
- **Listen in the pinned top bar.** A "▶ Listen ↗" button beside the song title, opening `https://www.youtube.com/watch?v=<id>` in a new tab (`rel="noopener noreferrer"`). The video is the one the analysis hears (`is_audio_source`), falling back to the primary, then the first video; hidden when the song has no video.
- **The standard** (`docs/ADMIN_UI.md`, referenced from CLAUDE.md, with reusable `.adm-list` classes in `admin.css`): (1) a list of items is a table with a header row, narrow fixed columns for choices and one flexible name column; (2) the thing the curator inspects (a link, a title) gets all the leftover width and is never squeezed by controls; (3) state is shown by a radio, checkbox or tag, not by a button that changes its label; (4) at most about three controls per row, and destructive actions are a small ✕ with a tooltip and a confirm; (5) density: panel body text 0.85rem, secondary text 0.75rem, `btn-sm` and `input-sm` controls, tokens only; (6) anything the curator needs while doing another task (such as listening while reading lyrics) is reachable from the pinned top bar, not by scrolling.
- Pure, node-tested helper for which video the Listen button and the table treat as the audio source, so the fallback rule lives in one place.

**Left to the builder.** Exact column widths, header label wording within the above, CSS names beyond `.adm-list`. **Follow-ups, not in this change:** apply the standard to the Links, Platform links, Lyrics and Details panels, and build the artist workbench to it (each its own small session).
